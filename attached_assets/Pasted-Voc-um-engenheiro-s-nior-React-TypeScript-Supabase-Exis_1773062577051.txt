Você é um engenheiro sênior React + TypeScript + Supabase.
Existe um bug crítico no fluxo de login do EncontraPet:
após fazer login com sucesso, o app não redireciona automaticamente
— o usuário precisa dar refresh manual na página para carregar o app.
Isso indica falha na escuta do estado de autenticação, não lentidão.

DIAGNÓSTICO — LEIA ANTES DE MEXER
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Causa provável 1 — AuthContext não está reagindo ao evento de login:
O onAuthStateChange do Supabase dispara 'SIGNED_IN' após login,
mas o contexto não está atualizando o estado ou o redirect
não está sendo chamado em resposta a esse evento.

Causa provável 2 — Redirect acontece antes da sessão estar pronta:
O navigate() está sendo chamado antes do Supabase confirmar
a sessão, então o ProtectedRoute barra o acesso e exibe tela branca.

Causa provável 3 — Race condition entre signIn e onAuthStateChange:
O signIn resolve, chama navigate(), mas o AuthContext ainda não
atualizou o estado — ProtectedRoute vê usuário null e redireciona
de volta para /auth, causando o loop/tela branca.

Após auditoria, aplique as correções necessárias:

### FIX 1 — AuthContext: loading state obrigatório

O contexto DEVE ter um estado initializing ou loading:

  const [loading, setLoading] = useState(true)

  useEffect(() => {
    // Verificar sessão existente primeiro
    supabase.auth.getSession().then(({ data: { session } }) => {
      setSession(session)
      setUser(session?.user ?? null)
      setLoading(false)
    })

    // Escutar mudanças de estado
    const { data: { subscription } } = supabase.auth.onAuthStateChange(
      async (event, session) => {
        setSession(session)
        setUser(session?.user ?? null)
        setLoading(false)
      }
    )

    return () => subscription.unsubscribe()
  }, [])

Exponha loading no valor do contexto.

### FIX 2 — ProtectedRoute: respeitar o loading

O ProtectedRoute NÃO pode redirecionar enquanto loading === true:

  const { user, loading } = useAuth()

  if (loading) {
    return (
      <div className="min-h-screen flex items-center justify-center bg-white">
        <div className="flex flex-col items-center gap-3">
          <span className="text-3xl animate-bounce">🐾</span>
          <p className="text-sm text-stone-400">Carregando...</p>
        </div>
      </div>
    )
  }

  if (!user) return <Navigate to="/auth" replace />

  return <>{children}</>

### FIX 3 — Página /auth: não chamar navigate() após signIn

O redirect deve ser feito APENAS pelo onAuthStateChange,
não pelo handler do form. Remova qualquer navigate() chamado
diretamente após o signIn:

  // ❌ ERRADO — causa race condition
  const { error } = await signIn(email, password)
  if (!error) navigate('/')

  // ✅ CORRETO — deixar o onAuthStateChange reagir
  const { error } = await signIn(email, password)
  if (error) setErrorMessage(error.message)
  // O AuthContext detecta SIGNED_IN e o ProtectedRoute
  // redireciona automaticamente quando user estiver setado

### FIX 4 — Verificar profile loading (se aplicável)

Se o AuthContext busca o profile do usuário após login,
garanta que o loading só vira false APÓS o profile ser carregado:

  onAuthStateChange(async (event, session) => {
    setSession(session)
    setUser(session?.user ?? null)
    if (session?.user) {
      await refreshProfile(session.user.id) // aguardar profile
    }
    setLoading(false) // só então liberar
  })
